# AgentOps — Relationships and End-to-End Testing Guide

This document is the reference for the database relationships and for verifying the app from a clean state. It is written so a group member or marker can reproduce the full CRUD workflow without knowing the implementation first.

---

## 1. System overview

```text
Browser
  ↓ REST API
Node.js + Express
  ↓ parameterised SQL
MySQL (agentops)
  ↓
Mock agent or optional Live AI provider
```

The browser never connects to MySQL directly. The backend is the only component with database credentials. Agent outputs are returned to the backend, validated, and then written to MySQL.

Default mode is `MOCK`: no API key, network, or paid service is required. Live mode is optional.

## 2. Table inventory

| Table | Primary key | Foreign keys | Main purpose |
|---|---|---|---|
| `users` | `id` | None | Human users and reviewers |
| `projects` | `id` | `owner_id → users.id` | Software-project workspaces |
| `agents` | `id` | None | Planner, coder, tester and reviewer agents |
| `tasks` | `id` | `project_id → projects.id`, `created_by → users.id` | Current task state and requirements |
| `task_dependencies` | `(task_id, depends_on_task_id)` | Both columns → `tasks.id` | Self-referencing task dependency graph |
| `task_assignments` | `id` | `task_id → tasks.id`, `agent_id → agents.id` | Which agents participate in a task |
| `agent_runs` | `id` | `task_id → tasks.id`, `agent_id → agents.id` | Execution history and status |
| `artifacts` | `id` | `task_id → tasks.id`, `agent_run_id → agent_runs.id` | Files or Markdown generated by an agent |
| `reviews` | `id` | `artifact_id → artifacts.id`, `reviewer_id → users.id` | Human review decisions |
| `ai_recommendations` | `id` | `task_id → tasks.id`, `recommended_agent_id → agents.id` | Assignee, risk and duplicate signals |

## 3. Complete relationship table

| Parent table | Child table | Relationship | FK column in child | Referenced column | Cardinality | Delete rule | Meaning |
|---|---|---|---|---|---|---|---|
| `users` | `projects` | User owns projects | `projects.owner_id` | `users.id` | 1 user : 0..N projects | `RESTRICT` | A project must have a valid owner |
| `users` | `tasks` | User creates tasks | `tasks.created_by` | `users.id` | 1 user : 0..N tasks | `RESTRICT` | A task keeps its creator reference |
| `users` | `reviews` | User writes reviews | `reviews.reviewer_id` | `users.id` | 1 user : 0..N reviews | `RESTRICT` | Review decisions remain attributable |
| `projects` | `tasks` | Project contains tasks | `tasks.project_id` | `projects.id` | 1 project : 0..N tasks | `CASCADE` | Deleting a project removes its tasks |
| `tasks` | `task_dependencies` | Task has dependencies | `task_dependencies.task_id` | `tasks.id` | 1 task : 0..N dependency rows | `CASCADE` | Deleting a task removes outgoing dependencies |
| `tasks` | `task_dependencies` | Task blocks other tasks | `task_dependencies.depends_on_task_id` | `tasks.id` | 1 task : 0..N dependency rows | `CASCADE` | Deleting a task removes incoming dependencies |
| `tasks` | `task_assignments` | Task is assigned to agents | `task_assignments.task_id` | `tasks.id` | 1 task : 0..N assignments | `CASCADE` | One task can involve multiple agents |
| `agents` | `task_assignments` | Agent receives assignments | `task_assignments.agent_id` | `agents.id` | 1 agent : 0..N assignments | `RESTRICT` | An agent with assignments cannot be silently deleted |
| `tasks` | `agent_runs` | Task has execution history | `agent_runs.task_id` | `tasks.id` | 1 task : 0..N runs | `CASCADE` | Deleting a task removes its run history |
| `agents` | `agent_runs` | Agent performs runs | `agent_runs.agent_id` | `agents.id` | 1 agent : 0..N runs | `RESTRICT` | Historical runs keep a valid agent reference |
| `tasks` | `artifacts` | Task owns generated artifacts | `artifacts.task_id` | `tasks.id` | 1 task : 0..N artifacts | `CASCADE` | Deleting a task removes its artifacts |
| `agent_runs` | `artifacts` | Run produces artifacts | `artifacts.agent_run_id` | `agent_runs.id` | 1 run : 0..N artifacts | `CASCADE` | An artifact always belongs to a run |
| `artifacts` | `reviews` | Artifact receives reviews | `reviews.artifact_id` | `artifacts.id` | 1 artifact : 0..N reviews | `CASCADE` | Deleting an artifact removes its reviews |
| `tasks` | `ai_recommendations` | Task receives AI signals | `ai_recommendations.task_id` | `tasks.id` | 1 task : 0..N recommendations | `CASCADE` | Recommendations are scoped to a task |
| `agents` | `ai_recommendations` | Agent is recommended | `ai_recommendations.recommended_agent_id` | `agents.id` | 0..1 agent : 0..N recommendations | `SET NULL` | An old recommendation survives if the agent is removed |

### 3.1 Table details

#### `users`

```text
users(
  id PK,
  username UNIQUE,
  email UNIQUE,
  password_hash,
  role,
  created_at
)
```

Stores human accounts. Used by projects (`owner_id`), tasks (`created_by`), and human reviews (`reviewer_id`).

#### `projects`

```text
projects(
  id PK,
  owner_id FK → users.id,
  name,
  description,
  status,
  created_at
)
```

One project can contain many tasks. A project has one owner in this MVP.

#### `agents`

```text
agents(
  id PK,
  name UNIQUE,
  role,
  provider,
  model_name,
  execution_mode,
  status,
  created_at
)
```

The four specialist roles are `PLANNER`, `CODER`, `TESTER`, and `REVIEWER`.

#### `tasks`

```text
tasks(
  id PK,
  project_id FK → projects.id,
  created_by FK → users.id,
  title,
  description,
  required_role,
  status,
  priority,
  estimated_hours,
  created_at,
  updated_at
)
```

`tasks.status` stores the current state. Historical execution details belong in `agent_runs`.

Valid statuses:

```text
TODO, IN_PROGRESS, BLOCKED, REVIEW, DONE, CANCELLED
```

#### `task_dependencies`

```text
task_dependencies(
  task_id PK/FK → tasks.id,
  depends_on_task_id PK/FK → tasks.id
)
```

This is a self-referencing many-to-many relationship. It represents:

```text
task A depends on task B
```

The composite primary key prevents duplicate dependency rows. A check constraint prevents a task from depending on itself.

#### `task_assignments`

```text
task_assignments(
  id PK,
  task_id FK → tasks.id,
  agent_id FK → agents.id,
  assignment_role,
  assigned_at
)
```

Allows a task to involve multiple agents, for example a PRIMARY coder and a SUPPORT tester.

#### `agent_runs`

```text
agent_runs(
  id PK,
  task_id FK → tasks.id,
  agent_id FK → agents.id,
  status,
  started_at,
  finished_at,
  latency_ms,
  input_summary,
  output_summary,
  raw_output,
  error_message,
  model_name,
  created_at
)
```

This is the execution history. A successful run is later connected to one or more artifacts.

#### `artifacts`

```text
artifacts(
  id PK,
  task_id FK → tasks.id,
  agent_run_id FK → agent_runs.id,
  artifact_type,
  file_name,
  file_path,
  content,
  created_at
)
```

Artifacts keep the actual generated Markdown/code text in `content`, so the UI can display it without an external file service.

#### `reviews`

```text
reviews(
  id PK,
  artifact_id FK → artifacts.id,
  reviewer_id FK → users.id,
  status,
  comment,
  created_at,
  reviewed_at
)
```

The human decision is kept separately from the AI output. This supports the human-in-the-loop workflow.

#### `ai_recommendations`

```text
ai_recommendations(
  id PK,
  task_id FK → tasks.id,
  recommendation_type,
  recommended_agent_id FK → agents.id NULL,
  score,
  reason,
  accepted,
  created_at
)
```

Recommendation types:

```text
ASSIGNEE, NEXT_TASK, RISK, DUPLICATE
```

The `accepted` field allows the system to preserve whether a human followed the AI recommendation.

**Expected UI**

### BLOCK-01 — Dependency blocking

**Steps**

1. In the seeded project, locate `Test login API`.
2. Make sure `Implement login API` is not done.
3. Try to run `Test login API`.

**Expected UI**

- The run is rejected.
- The error message mentions unfinished dependencies.

**SQL check**

```sql
SELECT
  blocked.title AS blocked_task,
  dep.title AS unfinished_dependency
FROM tasks blocked
JOIN task_dependencies td ON td.task_id = blocked.id
JOIN tasks dep ON dep.id = td.depends_on_task_id
WHERE blocked.project_id = 1
  AND dep.status <> 'DONE';
```

Expected: `Test login API` is listed with its unfinished dependency.

### SQL-01 — Relationship integrity queries

Run the following queries and confirm that no relationship is broken.

#### Tasks with their projects and creators

```sql
SELECT
  t.id,
  t.title,
  p.name AS project,
  u.username AS creator
FROM tasks t
JOIN projects p ON p.id = t.project_id
JOIN users u ON u.id = t.created_by
ORDER BY t.id;
```

#### Tasks with their assigned agents

```sql
SELECT
  t.id,
  t.title,
  ta.assignment_role,
  a.name AS agent,
  a.role
FROM tasks t
LEFT JOIN task_assignments ta ON ta.task_id = t.id
LEFT JOIN agents a ON a.id = ta.agent_id
ORDER BY t.id, ta.assignment_role;
```

#### Full run and review trace

```sql
SELECT
  t.title AS task,
  a.name AS agent,
  r.status AS run_status,
  ar.file_name,
  rev.status AS review_status
FROM tasks t
LEFT JOIN agent_runs r ON r.task_id = t.id
LEFT JOIN agents a ON a.id = r.agent_id
LEFT JOIN artifacts ar ON ar.agent_run_id = r.id
LEFT JOIN reviews rev ON rev.artifact_id = ar.id
ORDER BY t.id, r.id, ar.id;
```

#### Duplicate dependency check

```sql
SELECT task_id, depends_on_task_id, COUNT(*) AS occurrences
FROM task_dependencies
GROUP BY task_id, depends_on_task_id
HAVING COUNT(*) > 1;
```

Expected: no rows, because the composite primary key prevents duplicates.

#### Self-dependency check

```sql
SELECT *
FROM task_dependencies
WHERE task_id = depends_on_task_id;
```

Expected: no rows.

## 10. Troubleshooting

### `ECONNREFUSED`

MySQL is not running:

```bash
brew services start mysql
mysqladmin ping
```

### `ER_ACCESS_DENIED_ERROR`

Update the database credentials in `.env`:

```env
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=agentops
```

### `EADDRINUSE`

Port 3000 is already in use. Stop the old server or change:

```env
PORT=3001
```

Then open `http://localhost:3001`.

### Login fails after a database reset

Use the seeded account:

```text
alice@example.com
password123
```

If needed, rerun:

```bash
npm run db:setup
```

### Blank page

Check the server terminal for errors, then verify:

```bash
curl http://localhost:3000
```

If the server responds, reload the browser and check the browser console.
